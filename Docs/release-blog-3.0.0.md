# Hieronymus 3.0.0をリリースします

[前回のエントリ](https://www.beesnest-inc.com/blog/538)で「もう少し
「バリ取り」をしたらリリースする」と書いていましたが、バリ取りが
終わったのでリリースします。

前回のエントリで予告した「経費精算」と「通帳」の強化はそのまま入って
いますので、詳しくはそちらを見ていただくとして、今回は「バリ取り」で
何をやったかという話を書いておきます。3回の実データ投入を経て、
エントリを書いた時点では見えていなかったものがいろいろ見えました。

## 実データにぶつけて直したこと

弊社の実データで通帳を回すと、Excel起草の通りにいかない銀行とか、
妙な摘要とか、そういうのがいろいろ出てきます。

![画像: 通帳の取り込み画面](TODO)

地道な話なのですが、

- 取り込みから突合・起票までの冪等性（同じものを二度投入しても破綻しない）
- 「手数料は振込に合流する」の合流先の決め方
- 取り込んだ行から伝票への直リンク（明細単位のリンクは伝票を書き換えると外れるので、伝票そのものへのリンクにした）
- 突合の候補が取り込み後に古くなったら、失敗でなく「取り直し」にする

みたいなことを全部直しました。

あと地味に効いているのが、起票した時に**使用した学習ルールをトーストで
表示する**ようにしたことです。学習ルールは「隙あらば学習」で蓄積される
ので、間違ったルールが間違ったまま溜まっていると間違った起票が量産され
ます。表示するだけで「あ、このルールおかしい」と気づけるようになりま
した。

```
「隠れたルール禁止」ということにしています。
仕訳が勝手に決まってしまうのが怖いのは、なぜそうなったかが見えないからで、見えてしまえば対処は簡単です。
```

ホントに地味なのですが、こういうのが効くと「通帳を読み込ませるだけで
処理できる」が実際に成立するようになります。

## 計算書の読み取りを「転写」に戻した

前回、Amazonの意味不明な計算書を「いい感じに仕分ける」と書いたのですが、
あれをやるために一時期「構造化」させようとしていました。つまり、
AIに「この行は種別Xで、摘要はこうで…」という形で読ませて、後から
組み立て直す方式です。

これが失敗でした。LLMは「構造化」が下手です。頑張ってプロンプトを
工夫しても、行が増える・フォーマットが変わると崩れる。

で、方針を戻しました。**「全部の行をそのまま転写させる」**。これだと
LLMは多少マシになれば十分です。転写された行をどう仕分けるかは
ルールベース（前回書いた学習レイアウト）でやる。AIに「判断」をやめ
させると、一気に安定しました。

```
AIの使い方は前回のエントリの方針（「ここぞ」という箇所にだけ使う）と
変わっていないのですが、「転写」はLLMが一番安定してできる仕事です。
OCRとして使う分には、まあ、今のLLMは十分に実用になります。
```

これで、テキスト層のないPDF（画像として読むしかないAmazon支払明細書）
にも対応できました。

## ホームに「対応待ち」を出す

会計担当の日常は「何を処理し忘れているか」の確認に始まります。

そこで、ホーム画面に**「通帳の対応待ち」カード**を出すようにしました。
未照合（突合・起票待ち）と仮起票（実科目の伝票が入るのを待つ）の行が
口座名付きで並び、行をクリックするとその通帳へ飛びます。

![画像: ホームの対応待ちカード](TODO)

承認待ち伝票のカードと同じ体裁なので、会計担当はホームを見れば
「やること」が全部わかるようになりました。

## 権限を見直しました

AIを使えるようにして「現場の人」が入力するようになると、次に必要になる
のが権限の話です。「現場の人」には見せていいものと悪いものがある。

Hieronymusは元々、権限をAPI単位で管理していたのですが、これを機に
**230個あるエンドポイントを全部棚卸し**しました。

棚卸しはペルソナでやりました。

- **一般従業員**: 経費精算は書ける。でも立替金の受け取り処理は自分ではできない（経理がやる）。他人の証憑・精算書は見えない。承認されたら自分でも直せない
- **経理部員**: 会計データは全部見える・触れる。でも承認はできない。承認済みのデータは（本人が作ったものでも）一切操作できない
- **経理の偉い人**: 承認もできる。人事情報は見えるが人事は操作しない
- **営業**: 顧客管理・在庫管理はできる。会計も人事も見えない（案件の採算だけは見える）
- **管理者**: ユーザー権限の操作だけ。個々の業務は自分に権限を与えればできるが、管理者権限単体ではできない

これ、要するに「suが使えるからといって他人のメールを読まない」の
話です。実務的には管理者は全部の権限をONにすると思うのですが、
**ONにしないと読めない**のと**デフォルトで読める**のとは、事故の
起きやすさが全然違います。

![画像: ユーザー管理画面（権限チェックボックス）](TODO)

このペルソナごとの「できる・できない」を、全部テストとして書きました。
実際に穴が見つかって直したものもいろいろあります。例えば承認済みの
精算書に載った証憑は、本人でも削除できるようになっていました
（承認済み伝票はその証憑を指しているのに）。あとマイページの管理者
バイパスとか。「経理の偉い人」に人事情報を見せる権限が無くて、
**人事閲覧**という「見るだけ」の権限を作ったりもしました。

ついでに年度の確定を「管理権限のみ」に限定しました。全データを不変に
する操作なので、確定の取り消し（元々管理権限のみ）と対称にした方が
素直だという判断です。

```
棚卸しの途中で「403石碑」という現象に何度も遭いました。
権限は「許可表に載っていないものは拒否」のホワイトリスト方式なのですが、
エンドポイントを追加して許可表への登録を忘れると、その機能は誰にも403で
使えなくなります。実データ投入で「あれ？このボタン効かない」となる。
で、起動時に許可表と実際のエンドポイントを突き合わせて警告する仕掛けと、
未登録ゼロをテストで断言するようにしました。石碑は今後建たないはずです。
```

## AI設定とプロンプトの世代管理

前回のエントリで「読み取りプロンプトは特に難しいものではない」と
書きましたが、それでも調整はします。で、「configを書き換えて再起動」は
ダルい。

そこで**プロンプトをDBに「用途×世代」で保存する**ようにしました。
AI設定のページで、読み取り用のプロンプトをその場で編集すると
「次世代」として積まれて、即座に運用に載ります。変になったら
**「この世代を使用」**で一発で前の世代に戻せます。世代ごとに説明も
書けるので、「なぜこう変えたのか」が残ります。

![画像: AI設定ページ（プロンプトの世代管理）](TODO)

これは別にAIでなくても同じことで、設定ファイルの変更履歴が取れて
ロールバックできるというのは、地味に運用を楽にします。

## 精算書は「取引文書」でもある

経費精算書には顧客と案件を任意で入れられるようにしてありました。
これまでは精算書の中に閉じていたのですが、**案件を設定した精算書は
「精算書」という種別の取引文書として取引管理に現れる**ようにしました。

つまり、見積 → 納品 → 請求 → **精算書**という文書の流れの中に経費が
並びます。案件ごとに「この案件で経費がいくら出たか」が一目でわかる
ようになります。正は精算書側で、取引管理からは編集できない（精算書を
直せば同期する）という作りです。

## マニュアルを役割で書き直した

機能説明のマニュアルはある程度揃っていたのですが、「誰が最初の何を
読めばいいのか」が不明瞭でした。そこで、**役割ごとのクイック
マニュアル**を書きました。

- 従業員（経費精算の3ステップ）
- 上長・チームリーダー（承認だけする人の過ごし方）
- 経営層・社長（見るだけの人の画面案内）
- 経理（通帳担当の日常ルーティン）
- 個人事業主（1人で回す場合の「回し方」）

![画像: READMEの役割別リンク](TODO)

マニュアルを書くと穴が見つかるのは人間と同じで面白くて、書きながら
「伝票のリンクが従業員には落ちる」「担当者候補が取得できない」みたいな
不具合をいくつも直しました。マニュアルを書くのはテストの一種です。

（設定まわりも、ホームに散らばっていたのを「管理>設定」とそれぞれの
「設定」メニューに集約しました。マニュアルに「設定はここ」と書こうと
すると、散らばっていると書けないというのも理由です）

## まとめ

というわけでHieronymus 3.0.0をリリースします。

前回のエントリの後にやったことは、まとめると:

1. **実データで潰す**: 通帳・計算書の冪等性と安定化、学習ルールの透明化、ホームへの対応待ちカード
2. **権限を棚卸しする**: ペルソナ5役割の「できる・できない」をテストで固定、人事閲覧権限の新設、su原則
3. **AI運用の整備**: プロンプトの世代管理（ロールバック・説明）、読み取りは「転写」方式に回帰
4. **マニュアルの整備**: 役割別クイックマニュアル5冊と設定の集約

AI機能は前回書いた通り「OCRとルール作成」に留めているので、AIが使え
なくても運用できますし、地元のLLMでも動きます（引き続きGemmaで確認
済み）。より高度なことをしたければMCPから外部エージェントで、という
構成も変わっていません。

現時点でテストは445件通っています。ペルソナのケーススタディだけで
130件くらいあります。「その人にはこれができる/できない」が全部
テストとして書いてあるというのは、なかなか安心感があります。
