## Sticky（付箋・申し送り）機能の実装

### 目的と要件

通知や申し送りを書き、他の人にも通知する「Sticky」機能。
「画面に付箋紙を貼る」感覚で使えるミニマルな仕様:

- 全ページ（ナビバー・期ボタン横）でメッセージの有無（未読数バッジ）を通知
- クリックして閲覧・既読化できる
- 削除（自分宛コピー / 作者による本体削除）・他ユーザーへの転送ができる
- 削除しない限りいつでも見られる

### 既存資産の整理

`models/sticky.js`（Sticky: authorId, message）と `models/stickystatus.js`
（StickyStatus）はモデルだけ先行して存在していた。テーブルは環境によって
形状が異なる状態だった:

- 旧マイグレーション（20253125050713-create-sticky）は documentId ベースの
  旧構想（Stickies に documentId/receiverId、StickyStatuses 無し）
- 開発DBは後のモデル変更を sequelize sync が拾っていて
  （Stickies: authorId/message、StickyStatuses: posX/posY 等あり）、
  テストDBは旧マイグレーションで作られた旧形状だった
- 旧構想の「ページの座標に付箋を貼る」posX/posY は今回は採用しない
  （ユーザー判断: 一覧パネルで見る形にする）

### 実装

- **`migrations/20261115000000-rework-sticky-status.cjs`**（新規）:
  - Stickies: authorId/message を無ければ追加、documentId/receiverId/
    showHide/importance/completedAt を有れば削除
  - StickyStatuses: 無ければ作成（stickyId/receiverId/importance/readAt +
    timestamps）、あれば readAt 追加と posX/posY/showHide/completedAt 削除
  - **importance は「重要度」として温存**（ユーザー判断）
  - 環境差に耐えるため describeTable で列の存在確認をしてから操作
- **`models/sticky.js`**: `belongsTo(User, {as: 'author'})` を追加
  （表示名用 include に必要）
- **`models/stickystatus.js`**: showHide/posX/posY/completedAt を削除、
  readAt を追加
- **`routes/api_sticky.js`**（新規）+ `routes/api.js` 登録:
  - `GET /api/sticky` — 自分宛（StickyStatus経由）＋作者の未受信メッセージの

  - `POST /api/sticky/:id/forward` — 閲覧できるメッセージをそのまま転送。
    既に受信済みのユーザーには二重送信しない

  転送/削除ボタン、新規作成モーダル（本文＋宛先チェックボックス＋
  「全員に通知する」）、転送モーダル（宛先選択）。60秒ポーリング＋

### 追加対応: 403事故の修正と「宛先未指定 = 自分宛」

実機確認で POST /api/sticky が 403 になる障害を発見・修正:

- **原因: `libs/permission.js` の RULES に sticky が未登録だった。**
  guard の authorize は**どのルールにも一致しないパスをデフォルト拒否
  （403）**する。ハンドラ直呼びのテストは guard を通らないため検出漏れに
  なっていた（教訓: 権限ゲートの直下テストはルーティング層を通して初めて意味がある）
- **修正**: RULES に `{ match: /^\/sticky/, access: ANY }` を追加
  （付箋はログイン済み全員が使える。特定権限を要求しない設計のため ANY）
- 再発防止として、`test/sticky.test.js` に **guard を通す権限テスト**を追加
  （GET/POST/既読/転送/個人削除/本体削除の6パスが権限フラグなしユーザーで通ること）
- **宛先未指定の扱い**: ユーザーの感覚では「相手を指定しない = 自分のために
  書く」。POST で receiverIds が空のとき自分宛の StickyStatus を作るように変更
  （未読バッジが付くので自分の TODO として機能する）
- UI: 作成モーダルのボタンを宛先の有無で切り替え（誰か宛なら「送信」、
  自分だけなら「保存」）。宛先未選択時は「宛先を指定しない場合は自分宛の
  付箋（メモ）になります」と表示
- テスト: 宛先未指定テスト・権限テスト追加（15件合格）

  expense-dev のみに。メモの作者名は ogochan で解決されることを確認
- 残置している sample 系（user 24/31 と member 1）はマニュアルの
  スクショ・サンプルデータの主体なので削除していない。今後マニュアルを
  更新しないなら除去候補（ユーザー判断）

### ユーザー指摘と是正（サンプル主体の作り方）

ユーザー指摘「サンプルデータのためにユーザ名をいじったのだから、
テスト表示用のユーザを作って、必要ならデータのオーナーをそれに
変更（UPDATE）すべきだった」:

- 過去セッションは**実ユーザー（ogochan）の役職員紐付けを書き換えて**
  スクショの表示名を整えていたのが根本誤り
- 是正: member 1（サンプル太郎）を user 24（サンプル太郎・テスト表示用
  ユーザー）に紐付け（`UPDATE "Members" SET "userId" = 24 WHERE id = 1`）。
  サンプル精算書/伝票/案件担当者（member 1 参照）はすべてこの
  サンプル世界に閉じ込められ、ogochan の表示は実名に戻る
- user 31（expense-dev）もテスト表示用ユーザーであり、サンプル証憑の
  オーナーとして保持（ユーザー指摘の「テスト表示用ユーザー」のモデル自体は正しい
  やり方。誤りは実ユーザーへの流用）
