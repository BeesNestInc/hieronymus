# 2026-09-14 (Mon)

## 帳票PDFダウンロード時の401クラッシュを修正（my-company / init-*.js の自己HTTP呼び出し排除）

仕訳日記帳のPDFを落とすと `GET /api/company?kind=1 401` → `triggerUncaughtException`
でプロセスが落ちていた。続いて `GET /api/accounts 401` でも同様にコケた。
HTML表示は問題なし（`myCompany()` を呼ばないため）。

### 原因

- `libs/my-company.js` が `isBrowser` / `isNode` を関数呼び出しせず参照
  （関数オブジェクトなので常に truthy）。サーバ上でもブラウザ分岐に入り、
  セッションCookieなしの `axios.get('/api/company?kind=1')` 自己呼び出し →
  `guard` の `apiAuth` で401 → `routes/forms.js` に catch がなくクラッシュ。
- Node分岐も二重に壊れていた（`const company` のシャドウで外側に代入されず
  `undefined` を返す、`await import` の `default` 未取得で `models.Company`
  が undefined）。
- さらに `libs/init-{explanatory-journal,general-ledger,subsidiary-ledger,
  trial-balance,financial-statement}.js` も同様にサーバ上で axios 自己呼び出し
  （`/api/term|journal|ledger|accounts|accounts2|trial-balance`）しており、
  PDF生成パス全体が同じ401クラッシュの病巣だった。

### 対応

- `libs/my-company.js`: `isBrowser()` / `isNode()` 化、シャドウ解消、
  `default` import 修正、Sequelize結果を `toJSON()` でプレーン化。
  サーバ側はDB直読みになり401が出ない。
- 新規 `libs/server-data.js`（サーバ専用）: 上記6系統のAPIパスを
  HTTP経由せずDB/ロジック直読みで解決する dispatcher（axios と同じ `{data}` 形状）。
  呼び出し側は `import(/* @vite-ignore */ './server-data.js')` で動的importし、
  ブラウザバンドルに含まれないようにした。
- `routes/api_journal.js`: 本体を `fetchJournal(year, month)` として export 化
  （ハンドラは薄いラッパーに。レスポンス形状は従来通り `{journal}`）。
- `routes/api_ledger.js`: `get_details` を export 化（1語追加のみ。
  未コミットの `includeUnapproved` 対応とは同一行で重なるため同梱、
  server側は未指定＝承認済みのみの従来動作）。
- `init-*.js` 5件: `axios.get` → 環境分岐 `apiGet` に置換。
  Nodeでは `server-data.js`、ブラウザでは従来通り axios。
- `init-explanatory-journal.js` の `setupAccount()` の fire-and-forget を
  `await` 化（サーバでは科目マスタ到着前に `findAccount` が空振りするため。
  ブラウザ側も到着待ちになる分だけ堅くなる）。
- `routes/forms.js` 全6PDF分岐（日記帳・総勘定元帳・補助元帳・試算表・
  財務諸表・取引書類）と `routes/transaction_document.js` の `form_out` を
  `try/catch → next(err)` 化（`.then()` を `await` 化）。エラー時もプロセスが
  落ちず Express のエラーハンドラに委譲される。

### 検証

- 実DB（development, term=1）でサーバ側フローを端点まで実行:
  - `myCompany` → 自社名取得OK
  - 仕訳日記帳 12ヶ月、総勘定元帳 4帳票、補助元帳 3帳票、

## 帳票PDFのフォントが汚い問題を修正（Linux上のフォールバック解決）

PDF出力時の和文が潰れて汚い（読めるが粗い）と報告。HTML表示は綺麗だった。

### 原因

- 帳票CSSが Win/Mac 専用名のみ指定（`transaction.css`: Yu Gothic/Hiragino/
  Meiryo、`paperA4.css`: MS P明朝/ヒラギノ明朝）→ Linux上に存在せず全滅。
- ホストの fontconfig の和文デフォルト解決が `WenQuanYi Zen Hei`
  （Regularのみ）だったため、PDF生成側の headless Chromium が和文1文字
  残らず WenQuanYi で描画。実PDFの埋め込みフォントが
  `WenQuanYiZenHei` であることを抽出して特定。
- Regularしか無いフォントに太字指定（見出し等）がかかり合成太字に
  なっていたのも粗さの一因。
- `libs/print.js` の Google Fonts（Noto Sans JP）追加は三重の意味で
  救済になっていなかった：参照する `font-family` が無い（取引文書系）、
  到着待ちが無いまま `page.pdf()`、URLが400ウェイトのみで太字は
  合成太字のまま。

### 対応

- `transaction.scss`/`.css`: `font-family` 末尾に `"Noto Sans CJK JP"`、
  `"Noto Sans JP"`、`"IPAGothic"`、`"IPAPGothic"` を追記
  （既存の Win/Mac 指定は先頭に温存）。
- `paperA4.scss`/`.css`: body に同上、表3か所の明朝スタックに
  `"Noto Serif CJK JP"`、`"Noto Sans CJK JP"` を追記。
- `libs/print.js`: Webフォントを `wght@400;700` にし、
  `document.fonts.load` + `fonts.ready` の到着待ちを追加
  （5秒打切り、オフラインでも止まらない）。
- scss と css は中身を同一に手編集（css はベンダープレフィックス付き
  生成物のため差分最小化を優先）。

### 検証

- dist-ssr見積書＋編集後CSS＋新print.jsフローで再生成：
  埋め込みから WenQuanYi が消滅、200dpiレンダリング目視でクッキリ
  （取引文書系・台帳系とも。テキスト選択・検索性も維持）。
- `node --check libs/print.js` OK。
- ユーザーによる実PDFの目視確認済み。
