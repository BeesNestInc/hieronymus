## 新規画面に削除・伝票ボタンが出る不具合を修正

「新規入力」→保存→「新規入力」と辿ると、2回目の遷移先URLが現在URLと同一に
なるため `currentPage` store の変更検知が働かず `checkPage` が走らず、
古いvoucher（ID付き）が残り続けた。削除・伝票ボタンが出たままになり、
保存が新規作成ではなく既存レコードの更新になる恐れもあった。
保存直後に `replaceState` だけで store/state を同期していなかったことも一因。

### 対応

- `voucher.svelte` に `copyVoucher`（`on:copy`）を追加。
  親が同期的にIDなし新規voucherへ置き換えるため、URL同一時も確実にリセット。
  同一URL時は `replace` で履歴を汚さない。
- `voucher-entry.svelte` の保存（新規作成）後は
  `link(entryUrl, {replace:true})` で store/state も `entry` に同期
  （従来の素の `replaceState`＋手動GETと同等＋状態整合）。
- 非同期GET（entry取得・会社取得）にトークンガード（`pageToken`）を追加し、
  遅延到着した古いレスポンスでvoucherを上書きしないようにした。

### 検証

- `vite build` 成功。

## 新規複写画面で相手先を変更できない不具合を修正

キーを入力して選び直しても、その下の表示が元の会社のままだった。

### 原因

- `voucher-info` の `CompanySelect` への受け渡しが、他画面
  （`transaction-info`・`task-info` は `bind:` 双方向）と違って
  `voucher.company` からの一方向だった。選択後に親が再描画されると
  古い `voucher.company` の値が子に上書きされ、表示が元に戻っていた。
- 新規複写では会社情報の取得が非同期で後から届くため、この上書きが確実に発動し、
  取得完了がユーザー選択より遅いと選択自体も潰された。

### 対応

- `front/svelte/components/company-select.svelte`
  - 選択確定時（`companyDecide`）と登録保存時（`saveCompany`）に
    `decide` イベントで決定した会社オブジェクトを親に通知。
    登録キャンセル（`closeEntry`）では通知しない。
- `front/svelte/voucher/voucher-info.svelte`
  - `on:decide={syncCompany}` で `voucher.company` を同期。
- `front/svelte/voucher/voucher.svelte`
  - `fetchCompanyFor` にガード追加：取得完了前に `companyId` が変わっていたら
    上書きしない。
- 他の `CompanySelect` 利用箇所は `decide` を購読していないため影響なし。

### 検証

- `vite build` 成功。

## ブラウザバックでファイル欄が別証憑のものになる不具合を修正

何枚か証憑を見てからブラウザバックすると、ファイル欄が戻り先の証憑のものと
違った（リロードでは正しく表示）。

### 原因

- ファイル欄は `VoucherInfo` の `onMount` でしか取得していなかった。
  証憑→証憑の遷移ではコンポーネントが再利用され `onMount` が走らないため、
  前に見ていた証憑のファイルが残り続けた。

### 対応

- `front/svelte/voucher/voucher-entry.svelte`
  - `voucher.id` の変化に追従するリアクティブな再取得（`loadedFilesFor`＋
    `reloadFiles`、到着順ガード付き）を追加。リンク・バック/フォワード・
    新規保存後のいずれの切替でもその証憑のファイルを取り直す。
  - 新規画面の未保存アップロードは消さない配慮：
    IDなし→IDあり遷移で手元にファイルがある場合はそれを優先、
    別IDの残像がある場合のみクリア。
- `front/svelte/voucher/voucher-info.svelte`
  - `onMount` の重複取得を除去し取得元を親に一本化（金額・税の整形は維持）。
- `front/svelte/components/company-select.svelte`
  - ついでに、証憑切替時に古い検索候補・検索表示が残る条件
    （`companys.length===0` ガード）を除去。キー入力では `companyId` が
    変わらないため、ユーザー検索中の上書き心配はない。

### 検証

- `vite build` 成功。

## 証憑一覧の月選択が外れる不具合を修正

一覧で月を選んで証憑を開いて戻ると、月未選択に戻ることがあった。

### 原因

- `voucher.svelte` の `checkPage` が `status.params = url.searchParams` を
  全状態で実行していた。entry/new のURLにはクエリがないため、一覧の
  絞り込み条件が空で上書きされ、「もどる」（`closeEntry`）が空条件で
  一覧に戻っていた。

### 対応

- `status.params` の更新を `list` 表示時のみに限定。
  `entry`/`new` では上書きしないため、証憑を開いて戻っても
  月・種別・相手先などの絞り込みが保持される。

### 検証

- `vite build` 成功。

## 証憑種別マスタの保存403とプログラム「なし」選択肢の欠落を修正

証憑種別を追加して保存すると `AxiosError 403` で `Uncaught (in promise)` になった。

### 原因

- `libs/permission.js` に `PUT /voucher/classes` のルールがなく、
  `authorize()` のデフォルト拒否に落ちて管理者でも必ず403になった
  （2026-08-18導入の宣言的認可での漏れ。それ以前はチェックなしで誰でもPUT可）。
- フロント `table-maintenance` は `axios.put` のエラーハンドリングがなく、
  そのまま未捕捉 rejected として表面化した。

### 対応

- `libs/permission.js`
  - `{ match: /^\/voucher\/classes\/?$/, methods: ['PUT'],
    access: ['administrable', 'accounting', 'companyManagement'] }` を追加。
  - `administrable` は設定画面（`home.svelte` は管理者のみ表示）のため、
    `accounting` / `companyManagement` は他種別マスタとの整合のため含めた。
- `front/svelte/widgets/voucher-classes.svelte`
  `front/svelte/home/home.svelte`
  - 「プログラム名」ドロップダウンの先頭に `[ '', 'なし' ]` を追加。
  - DBは空文字/NULLを「なし」扱い（seedは `form: ''`、初期値はNULL）、
    判定側も `if (book.form)` のfalsyチェックのため空文字保存で動作する。

### 検証

- guard単体テスト: administrable / accounting / companyManagement → ALLOWED、
  権限なし → 403 DENIED。
- `tax-calc.test.js` 14件パス。
- `vite build` 成功。
