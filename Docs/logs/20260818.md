# 2026-08-18 (Tue)

## 伝票入力MCP と API認証・認可・サーバ権威計算

伝票入力を目的とした MCP サーバの実装と、それを支えるAPI基盤の整備を実施した。

### 方針

- 非会計ユーザーは画面を使わずに（MCP経由で）伝票・証憑を入力できる
- その伝票は承認待ちとなり、会計権限のあるユーザーが承認する
- 税額計算・貸借一致検証は **サーバ側で権威計算**（クライアント値を信用しない）
- APIの認証・認可が未整備だったため、これを一括で整備

### 実装内容

#### Phase C: API認証・認可

- `libs/permission.js` を新設
  - 全 `/api` に認証必須化（公開は `user/login`・`user/signup`・`setup`・`version` のみ）
  - 宣言的認可ポリシーを一本化。`accounting` / `fiscalBrowsing` / `approvable` / `companyManagement` / `administrable` 他でルートを定義
  - 未認証は 401、権限不足は 403（`{code:-10, message}`）
- `routes/api.js` に `guard` を適用
- `routes/api_cross_slip.js` の POST から accounting 必須を撤廃（非会計ユーザーの入力を許可）
- `routes/api_voucher.js` の update/delete に作成者-or-accounting の所有権チェックを追加
- `GET /api/cross_slips/not_approved` の term フィルタをセッション term 未設定時は省略するよう緩和（API接続ユーザーでも自分/全体の承認待ち一覧が見える）

#### Phase A: サーバ権威計算

- `libs/tax-calc.js` を新設（フロントの `computeTax`/`makeTaxLine`/`findTaxClass` と同一アルゴリズム）
  - `roundingMethod` は明示引数化しモジュール状態に依存しない純関数化
  - `recalcSlipLines` / `validateDay` / `validateLines` / `validateBalanced` / `computeVoucherTax`
- `routes/api_cross_slip.js` の POST / PUT で再計算＋検証、不整合は HTTP 422 + `{code:-2, message}` で拒否
- `routes/api_voucher.js` の POST / PUT で証憑の税額をサーバ計算（取引先存在確認付き）

#### Phase B: MCP サーバ `mcp/voucher-mcp/`

- 構成: `index.js` / `client.js`（axios+CookieJar, ensureLogin） / `definitions.js` / `handlers.js` / `tax.js`（プレビュー用）/ `validate.js`（必須項目チェック）
- ツール 17種: 読取 8 / 書込 8（作成・更新・承認・不承認・削除・証憑）/ 税額プレビュー
- `HIERONYMUS_READONLY=1` で書き込み抑止
- 登録: `~/.config/opencode/opencode.jsonc` の `mcp` に追加（要 ユーザー/パスワード設定）

### 動作確認（実環境）

- `opencode` ユーザーを登録（accounting=false / approvable=false / fiscalBrowsing=true）
- opencode 再起動後、`~/.config/opencode/opencode.json` の `voucher-mcp` が実動作することを確認
  - SDKクライアントで起動→17ツールが読み込まれる
  - `get_voucher_classes` / `get_companies` / `get_fiscal_year`(term 2, 2025年度) が実データで取得成功
- 現行年度（term 2, 2025-08-01〜2026-07-31）は **税込方式（taxIncluded=true）** のため、伝票の税額はサーバ計算で 0 になる想定
- 承認は `approvable=false` のため opencode ユーザーでは不可。承認は会計権限ユーザーで実施する運用

### トラブルシュート: MCPツールが見えない

- 当初グローバル設定を `~/.config/opencode/opencode.jsonc` に置いたが、**グローバル設定は `opencode.json`（拡張子 .json）しか読まれない**（公式ドキュメントの Locations/Global 参照）。
  `.jsonc` はプロジェクト設定では有効だが、グローバルではロードされない。
- 対処: `~/.config/opencode/opencode.json` に移行し `.jsonc` は削除。openode を再起動すれば `voucher_mcp_*` ツールが読み込まれる。

### 教訓・メモ

- MCP側の事前検証は「サーバが税行(114/308)を追加する前」の状態では貸借一致を判定できない。権威はサーバなので、MCP側の事前検証は必須項目のみに絞る（貸借一致はサーバの422に委ねる）
- 月間通し番号は `MonthlyLog` が採番し、明細失敗時のズレが起こりうる既知の課題あり（今回は範囲外）
- テストDBは `config/test` を新規作成してマイグレーション済み。本番/開発DBには一切触れていない

### 証憑OCRのPDF対応とモデル設定（Legion describe-image-mcp）

- 目的: 証憑（画像/PDF）を「空気読み」で自動仕訳する前段の OCR 経路
- **PDF対応（Option C）**: Legion に `pdfjs-dist`(6.2.108) + `@napi-rs/canvas`(1.0.7) を追加
  - `describe-image-mcp` に PDF→PNG（1ページ目、scale 2）変換を実装し `describe_image` が PDF を直接受付
  - 検証: 実PDF（見積書テスト.pdf）を「会社名/金額/税/請求番号」のJSON抽出成功
- **モデルを config.llms で設定可能に**:
  - `makeModel()` ベースへ切替（google/GEMINI_API_KEY のハードコード廃止）
  - `config/config.yaml` に `llms.vision: mimo_standard`（**MiMo-v2.5**、opencode.ai zen/go 経由）を追加
  - `DESCRIBE_IMAGE_MODEL=<llmsキー名>` で切替可能（`gemini_standard` への切替も確認）
- `config/mcpServers/describe-image.yaml` に `CONFIG_DIR` を設定（config.llms 解決のため）
- 依存: Legion root package.json と describe-image-mcp/package.json に明示追加
- Legion コミット: `2a559bb`（beesnest）
