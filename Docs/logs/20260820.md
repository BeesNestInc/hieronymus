## 免責しやすいAPIパラメータエラーの防止（3層対応）

MCP経由の `list_vouchers` を `date`/`month` 無しで呼んだ際に
`FiscalYear.findOne({ where: { term: undefined } })` で Sequelize が
`WHERE parameter "term" has invalid "undefined" value` をスローし
プロセスを巻き込む形のクラッシュが発生していた。

原因: `/api/user/login` は `req.session.term` を設定しない（term は
画面ルート `home.js` / `api_setup.js` のみが設定）。そのため MCP の
`list_vouchers`（date/month 任意）が term 未設定のまま該当パスに到達する。

### 対応1: サーバ側ガード（hieronymus）

- `routes/api_voucher.js` `GET /api/voucher`
  - `date`/`month` が無い場合に `req.session.term` 未設定なら
    HTTP 400 + `{code:-2, message:'会計年度(term)が未設定です。...'}` を返す
  - `req.params.order` → `req.query.order` の既存バグ修正
  - `get()` の2本の `.then` チェーンに `.catch(next)` を追加（async rejectの疎通先確保）
- `routes/api_transaction_document.js` `POST /api/transaction`: `body.no` 未指定時に
  term 未設定なら 400 を返すガードを追加
- `app.js` エラーハンドラ: `/api/*` は HTML ではなく JSON `{code:-500, message}`
  を返すように（画面ルートは従来のHTMLのまま）→ MCP側で読めるエラー面を確保

### 対応2: MCP側の実行前検証（voucher-mcp）

- `list_vouchers` ハンドラ: `date`/`month` のどちらか必須とし、両方欠如なら
  API呼び出し前に明確なエラーを throw
- `definitions.js` の説明に「month または date の指定が必須」を明記

### 対応3: スキルでの必須パラメータ指示

- `ai/skills/voucher-entry/SKILL.md`（hieronymus）
- `roles/accounting/skills/voucher-entry/SKILL.md`（Legion）
- 一覧取得（`list_vouchers` / `get_journal`）は必ず `month`/`date` を指定し、
  該当年月の会計年度は `get_fiscal_year` で先に確認する旨を追記

### 検証

- テストDB（`NODE_ENV=test`, PORT=3100 の一時起動）で再現:
  - `/api/voucher` パラメータ無し → 400 + `{code:-2, message}`（クラッシュ無し）
  - `?month=2026-03` / `?date=2026-03-25` → 200 `{code:0, vouchers:[]}`
  - MCP経由: `list_vouchers({})` → 事前検証エラー / `list_vouchers({month:'2026-03'})` → `[]`
- unit + e2e: `test/tax-calc.test.js test/e2e.test.js` 18件 pass

## 原価計算方針の文書化（しまパン）

「しまパン」の棚卸しに必要な原価計算について、方針を文書化した。

### 内容（第1版）

- 評価方法: 品種（SKU）単位の総平均法（期末一括）
- 原価範囲: 仕入価格（円換算）＋付随費用（運賃・保険・関税・通関）をロットの仕入金額で按分
- 為替: 仕入時の適用レート、差額は為替差損益
- 在庫数量: しまぱん.COM＋FBA＋実地棚卸の突合
- 決算: 既存の三分法を維持（借:商品 1060000／貸:期末商品棚卸高 7020010）

### 在庫管理モジュールの設計（更新版）

振替伝票と同様の「在庫移動伝票」を主とし、会計伝票を自動生成する運用に更新。
本セッションで設計を詰め、以下の結論とした:

- **在庫移動伝票を主、会計伝票(CrossSlip)を従** — 在庫伝票の保存時に会計伝票を自動生成し相互リンク
- **倉庫マスタ**（しまぱん.COM倉庫 / FBA倉庫 など）を導入し、伝票で移動元/移動先を指定
- **移動平均法**（仕入の都度更新。期中の出庫単価が随時確定）に変更
- **明細は常に単価を持つ**（入庫: 実績原価、出庫・調整: 評価単価）
- 伝票種別: 仕入入庫 / 売上出庫 / 倉庫間振替（会計なし）/ 棚卸調整 / 廃棄
