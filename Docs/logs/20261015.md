## AI API error: 400 の原因と対応

- ユーザー環境は openai-compatible → opencode.ai zenゲートウェイ +
  muse-sparkモデル。400の正体は3連発だった:
  1. `MissingSessionID`: ゲートウェイは `x-opencode-session` ヘッダ必須。
     `openaiHeaders()` で自動付与（Legionと同名）。`llms.headers` 素通しも対応
  2. `Model does not support this protocol`: muse-spark系は互換APIではなく
     完全なOpenAIプロバイダ（`createOpenAI`）が必要。Legionもモデル名で
     使い分けているため同様に実装。`provider: openai` を追加
  3. `'additionalProperties' is required`: strict構造化出力のため
     スキーマに `additionalProperties: false` + required全列挙を追加
- 実ゲートウェイ経由の疎通確認済み
- テスト分離: 実config/llms.jsonにキーが入るとテストが影響を受けるため
  `LLM_CONFIG_PATH` でfixture参照可にし、`test/fixtures/llms-test.json` を使用

## AI読み取りスピナー固着の調査と番犬追加

- 症状: /ocr 200（64秒）後もスピナーが残り、秒数も停止。
  タブ切替なしの目視確認あり。実ブラウザ再現（2.7MB画像・24秒応答）では
  正常終了し、固着は再現できず
- 調査結果:
  - `pageerror: w` はminified AxiosError（ロード時の401/403未処理。
    従来からのノイズで本件と無関係）
  - finallyは必ず実行される構造＋axios 180秒timeoutのため永久固着は
    構造上不可。秒停止＝clearInterval到達＝finally実行済みのはずだが
    描画に反映されていない点が未解明
- 対応: 応答なし番犬（200秒・responded確認付きで誤爆なし）と
  finally到達のconsole.logを追加。次回発生時はF12コンソルの
  `aiRead done` 有無で「応答未達」か「描画未反映」かを切り分ける

## スピナー固着の真因：トーストの重複キーで更新が例外死

- コンソールに `Cannot have duplicate keys in a keyed each` + `aiRead done`。
  finallyは実行済み（状態リセット済み）だが描画が死んでいた
- 真因: svelte-toastsのuidが `Date.now()` のため、aiReadの警告＋完了の
  2連トーストが同一ミリ秒に発行されると重複キーになり、Svelteのflush
  全体が例外で吹き飛ぶ。以降のDOM更新（スピナー解除含む）が止まる
- 対応: 自前ラッパー（common/toast.svelte。全トーストのfunnel）で
  同一ミリ秒のshowを1ms以上ずらして衝突を防止。アプリ全体に有効
