## AI API error: 400 の原因と対応

- ユーザー環境は openai-compatible → opencode.ai zenゲートウェイ +
  muse-sparkモデル。400の正体は3連発だった:
  1. `MissingSessionID`: ゲートウェイは `x-opencode-session` ヘッダ必須。
     `openaiHeaders()` で自動付与（Legionと同名）。`llms.headers` 素通しも対応
  2. `Model does not support this protocol`: muse-spark系は互換APIではなく
     完全なOpenAIプロバイダ（`createOpenAI`）が必要。Legionもモデル名で
     使い分けているため同様に実装。`provider: openai` を追加
  3. `'additionalProperties' is required`: strict構造化出力のため
     スキーマに `additionalProperties: false` + required全列挙を追加
- 実ゲートウェイ経由の疎通確認済み
- テスト分離: 実config/llms.jsonにキーが入るとテストが影響を受けるため
  `LLM_CONFIG_PATH` でfixture参照可にし、`test/fixtures/llms-test.json` を使用
