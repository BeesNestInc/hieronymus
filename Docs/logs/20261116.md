## dev DB のサンプル/テストデータ混入の正常化

ユーザー報告「自分（ogochan）が書いたメモの作者名が『サンプル太郎』になる」:

### 原因

stickyのバグではなくデータの問題。`displayName` は全画面共通の規約で
Memberの氏名（tradingName/legalName）をUser.nameより優先する。dev DBに
`Members.userId = 1`（ogochan ⇔ member 1 サンプル太郎）の紐付けがあり、
精算・案件など他画面でも同じ表示になっていたはず。

### 経緯の確認

- Docs/session.md「dev DBは匿名化・サンプル化済み（サンプル太郎等）」の通り、
  **マニュアル用のサンプルデータ**として意図的に作られたもの
- ただしスクショ用に**実ユーザー（ogochan）の役職員紐付けを書き換えて**
  表示名を整えていたのが根本誤り（ユーザー指摘により後述の是正を実施）

### 撮影時の発見: 3011ポートのサーバーが古かった

- ポート3011で稼働していたサーバーは**11/14 23:52起動・PPID 1の
  バックグラウンドプロセス**で、sticky API未実装のまま（guardの
  デフォルト拒否で403）。新しいdistフロントは静的に更新されるため
  「UIは新/バックエンドは古」の状態だった
- **これは本作業の前セッションが起動して放置したもの**。11/14深夜に
  マニュアルのスクショ撮影（manual-shots-*.mjsはBASE=3011）のため
  `PORT=3011 node ./bin/www` をバックグラウンド起動し、停止せずに
  セッションを終えていた。ユーザーの指摘で発覚し、11/16 15:44に停止した
- なおユーザーは**常に3010でテストしていた**（3011を使ったのはスクショを
  撮ろうとした本セッションだけ）。実機テストの403報告は3011とは無関係で、
  RULES未登録という実バグだった（修正済み）
- 現行サーバーはポート3010（APP_NAME=hieronymus-dev、11/16 00:22起動、
  ユーザー起動）。撮影は3010に対して実施
- **教訓**:
  - 静的ビルドのフロントはプロセスを再起動しなくても新しくなる。
    「UIは動くのにAPIが403/404」のときは、稼働中プロセスの起動時刻を確認する
    （`ps -o pid,ppid,lstart,cmd -p <pid>` + `ss -ltnp`）
  - AIセッションがバックグラウンドで起動したサーバーは**セッション内で
    必ず停止する**。PPID 1 の放置プロセスは「動き続ける古いコード」として
    後日別の障害に見える
