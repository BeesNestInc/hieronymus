# 2026-11-16 作業ログ（その2）

## 予定表（資金繰り予定）機能の実装

### 方針

前々からの要望「月々決まった入出金・資金繰りに影響する入出金の予定表」。
ほとんどの環境には既にグループウェア/カレンダーがあるので、**別系統の
カレンダーシステムを作るのはナンセンス**というユーザーの問題意識から:

- **予定データ（会計データ）は Hieronymus に持つ**。金額・方向・繰り返し
  ルールを持つデータはグループウェアのイベントカレンダーには属さない
- **カレンダー表示はICSフィード配信で既存システムに任せる**
  （Googleカレンダー、Legionカレンダー等どこからでも購読可）
- 月次の一覧はカレンダーグリッドでなく単純な表（月次リスト＋月計）
- 実績（通帳・仕訳）との突合は次フェーズ

ユーザー決定: ICS配信で両対応 / 繰り返し＋単発 / 突合は後回し /
**閲覧も権限限定**（ただし会計閲覧権fiscalBrowsingは「偉い人用の閲覧権限」
という設計意図なので、入出金予定自体の閲覧には含めてよいと確認済み）

### 実装

- **マイグレーション `20261116100000-create-schedules.cjs`**:
  Schedules テーブル（title/kind in,out/amount/recurrence monthly,once/
  dayOfMonth(0=月末・末日繰り上げ)/date/note/enabled）+ Users.feedToken。
  環境差に耐える防御的実装（describeTable確認）
- **`models/schedule.js`**（新規）+ models/index.js・user.js 更新
- **`routes/api_schedule.js`**（新規）:
  - `GET /api/schedule/:year/:month` — 展開済み予定（日付順）+ 月計
    （入金計/出金計/差引）
  - `GET /api/schedule` — 定義一覧 + 自分のフィードトークン
    （**トークン未発行なら初回アクセス時に発行**）
  - `POST /api/schedule` / `PUT|DELETE /api/schedule/:id` — CRUD（バリデーション付き）
  - `POST /api/schedule/token` — トークン再生成（旧トークン失効）
  - `GET /api/schedule/feed?token=xxx` — **ICSフィード（トークン認証）**。
    展開済み個別VEVENT（RRULE不使用。31日→2月28日等の繰り上げをサーバで解決。
    UID=`scheduleId-date@hieronymus` で購読側の重複排除）。終日イベント。
    展開範囲は先月〜12ヶ月後。存在しないトークンは404（列挙防止）。
    失効ユーザーのトークンも404
- **`libs/permission.js`**: 閲覧 `accounting/fiscalBrowsing/administrable`、
  編集 `accounting/administrable`。**PUBLIC_PATHS に `GET /schedule/feed`**
  （トークン認証はハンドラで。guardは未登録パスをデフォルト拒否 —
  stickyの403事故と同じく必須）。guard通しの権限テストを含める
- **フロント `front/svelte/schedule/schedule.svelte`**（新規）:
  月切替（URLクエリ ?ym=YYYY-MM）、月次一覧＋月計、定義一覧（編集/削除）、
  作成・編集モーダル（種別ラジオ/金額/毎月-単発/発生日/備考/有効）、
  フィードURL表示（コピー・再生成）。`index.svelte` にルート追加、
  `config/module-list.js` にメニュー「予定表」（icon: bi:calendar-week）追加

### 実装中に遭遇した問題

- **URLクエリなしの初回ロードで表示が空**（「undefined年undefined月」）:
  ym監視の比較 `ym !== lastYm` が初期値null同士で偽になり、初回処理が
  スキップされていた。初期値を 'init' にして解決
- **備考に「null」と表示**: `{item.note}` に null が渡っていた。`note || ''` に修正
- **フィードトークンが空のURLが表示される**: トークンは再生成時しか発行してい
  なかったため。list アクセス時に未発行なら自動発行するよう変更
- **スクショで期表示が第1期になる**: 一時サーバー（3012）で直URLアクセス

  （/home/2 のセッション引き継ぎ）で第2期に。原因は最後まで完全には
  追えなかったが、サイドバー経由で解決した

## 予定表: カレンダービュー・年ビューへの改修

### 変更内容

- **月ビュー**: 月次リストを**カレンダーグリッド**に変更（日曜始まり）。
  セルにその日の予定を入金=緑/出金=赤のチップで表示（hoverで金額）。

  月名クリックでその月のカレンダーへ。処理月をハイライト
- **予定の一覧**: 従来「予定の定義」として別表だったものを、表示順切替付き
  の一覧に。「発生日順（既定）/金額順/種別順/登録順」をクライアント側ソート。
  月次リスト表は削除（カレンダー＋一覧で代替）

## 予定表: 繰り返し予定の「この月だけ編集」

ユーザー要望「『繰り返しイベントだけど今回だけ編集』と『繰り返しイベント全部編集』
の両方。ざくっと金額を入れておいて、確定したら本当の金額を入れる」:

### 実装

- **マイグレーション `20261116120000-create-schedule-overrides.cjs`**:
  ScheduleOverrides テーブル（scheduleId+date で一意索引。date は展開後の
  実発生日。deleted=true でその月の予定自体を取り消す）。単発予定には使わない
- **`models/scheduleoverride.js`**（新規）
- **API**: `PUT /api/schedule/override`（上書き/取り消しの upsert。値を省略すると
  元の予定の値を引き継ぐ）、`DELETE /api/schedule/override/:scheduleId/:date`
  （毎月の予定に戻す）。月次・年次・ICSの展開はすべて個別設定を適用した値で
  計算される。一覧レスポンスに overrides を追加
  （ルート登録は `PUT /schedule/:id` より先。権限は既存の編集ルールが吸収）
- **UI**: カレンダーの予定をクリックして開くと「この月だけ変更する /
  毎月の予定を変更する」のラジオ（既定はこの月だけ）。個別設定済みの
  発生には「毎月の予定に戻す」ボタン。「予定の一覧」に「個別設定 ×n」
  バッジ。カレンダーチップのツールチップに個別設定ありを表示

### 実装中に遭遇した問題

- **「新規」でモーダルが開かない**: openEditor のリライトで `base` を
  schedule 未定義のまま計算し、新規登録時（schedule === undefined）に
  `schedule.title` 参照で例外。評価を schedule の存在確認でガードして解決
- **カレンダーチップから個別変更にならない**: buildWeeks が生成するセルに
  `date` を入れていなかった（テンプレートの `cell.date` が undefined →
  カレンダークリックが常に「毎月の予定」モードになった）。セルに date を追加
- **スクショの期表示が不定**（第1期/第2期が run ごとに揺れる）: 原因は最後まで
  特定できず。スクリプト側でナビ表示に「第2期」が出るまで /home/2 を
  再アクセスする待ちループを入れて決定的にした

### 検証

- テスト追加9件（差し替え/値引き継ぎ/一意制約upsert/この月の取消し/
  毎月への復帰/単発は不可/年次集計反映/ICS反映/guard権限）で28件合格
- 全体: 218 passing / 1 failing（無関係な既存問題）

  カレンダーはグレーチップ、月計（入出金）には含めない
- 種別順ソートは 入金→出金→予定、ICSでは (予) プレフィックス

### 自動起票の構想はTODOに記録のみ

「わかってるものは自動で起票してもいいんじゃね？」については実装せず
TODO.md に記録（月次予定の自動ドラフト起票＋通帳取込との消し込み案。
過ぎた予定の突合価値の検討も含める。優先度低）

### 金額0の保存

「金額が0だと変更できない」: フロントの canSave が amount > 0 を要求して
いた。>= 0 に緩和（サーバは元々0許可）。ざっくり0円→確定時に個別変更の
運用に対応

### 「予定」種別の保存

「予定の保存ができない(disabledのまま)」: 新規モーダルの金額初期値 null で
canSave が偽のまま。「予定」種別は金額任意（省略時0）とし、新規の金額
既定値を0に変更。出金/入金は従来どおり金額必須

### カレンダーセルクリックでその日の予定登録

「『無』をクリックしたら、その日の予定登録になって欲しい」:

- 日セル（余白を含む）クリックで、その日付・単発の新規登録が開く
- チップのクリックは stopPropagation で分離（チップ=編集/セル=新規登録）
- 一時サーバー3012で動作確認（空セル→2026-11-01の新規、チップ→個別変更、
  予定ありセルの余白→その日の新規）後、停止

### 「予定」種別の金額欄

「『予定』の時に金額が0円で出るのはみっともない。金額入れられないことにして
空欄にしよう。金額が必要なのは入金か出金」:

- 編集モーダル: 種別が「予定」のときは金額欄を非表示（両モードとも）
- 予定の一覧: 「予定」の金額セルは空欄（"0円"を出さない）
- カレンダーチップのツールチップ: 「予定」は金額を表示しない
- ICS: 「予定」のDESCRIPTIONに金額を含めない（備考だけ）
- DB上のamountは0のまま（表示だけ空欄扱い）。テスト1件追加（32件合格）

### ICS配信の実装方式をマニュアルに明記

ユーザーの質問「ICSって繰り返しの予定って作れないんだっけ？」を受けて、
RRULE はあるが本システムは**RRULE を使わずサーバ側で展開した個別VEVENT
として配信している**ことを documents/schedule.md のICS購読節に追記した
（理由: 末日繰り上げがRRULEで表現できない / 個別設定の例外をRRULEの
EXDATE・RECURRENCE-IDで表現するとクライアント差が出る / 窓は再取得で
スライドするため実用上問題なし）。
