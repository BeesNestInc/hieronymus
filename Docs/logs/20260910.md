# 2026-09-10 (Wed)

## 証憑入力の相手先インクリメンタル検索が動作しない不具合を修正

`/voucher/new` で「相手先」の検索キーを入れると
`Uncaught TypeError: can't access property "forEach", b is undefined`
（`company-select.svelte:119`）が出て候補が出ない事象を調査・修正。

### 原因

- `company-select.svelte` の `onUserInput` が `original_companies.forEach`
  を無条件で呼び、`GET /api/company/` の完了前にキー入力されると
  `undefined` 参照で例外になった。
- さらに実測で `GET /api/company/`（末尾スラッシュ付き）が
  `libs/permission.js` のガード正規表現 `/^\/company(\/\d+)?$/` に不一致で
  **403 permission denied** になっていた。会社一覧が一度も取得できないため、
  ガード後はクラッシュしない代わりに入力に無反応だった。
  （`GET /api/company` は 200 正常）。

### 対応

- `company-select.svelte`
  - `onUserInput` / `clearInput` に `original_companies` 未取得ガード。
  - 取得URLを `/api/company${param}`（スラッシュなし）に変更。
  - 一覧取得前に打たれた検索キーを取得完了後に再フィルタ（`onMount` 内で1回のみ）。
  - 検索一致判定を `.match` → `.includes` に変更
    （`(` 等の入力で正規表現例外を起こさない）。
  - 取得失敗時の `.catch` ログ追加。
- `libs/permission.js`
  - 会社GETルールを `/^\/company(\/\d+)?\/?$/` に緩和（末尾スラッシュ許容）。
  - サーバ再起動後に有効。

### 検証

- API: `/api/company`、`/api/company/`、`/api/company?clientOnly=true`
  いずれも 200 で一覧返却を確認。
- Playwright（開発DB）: `/voucher/new` で「hieronymus」→「Hieronymus株式会社」、
  「ゆうひ」→「ゆうひ銀行」と候補表示、ページエラーなし。
- `vite build` 成功。

## 証憑保存時の DataCloneError を修正

新規証憑の保存後に
`Uncaught (in promise) DOMException: The object could not be cloned.`
（`voucher-entry.svelte:167`）が出る事象を調査・修正。

### 原因

- `voucher.svelte` の `checkPage` が共有 `status` に
  `status.params = url.searchParams`（`URLSearchParams`）を代入。
- `URLSearchParams` は structured clone 不可のため、
  保存後の `window.history.replaceState(status, ...)` が `DataCloneError` になった
  （Node の `structuredClone` でも再現確認）。
- `history.state` はどこからも読まれていない
  （`onpopstate` は `location` 参照）ため、渡す意味がなかった。

### 対応

- `voucher-entry.svelte` / `company-entry.svelte`（同一パターン）の保存後遷移を
  `replaceState({ page: entryUrl }, "", entryUrl)` に変更
  （`router.js` の規約に合わせた clone 可能な値）。

### 検証

- `vite build` 成功、dist に両修正を含むことを確認。
- Playwright E2E（開発DB）: 検索→候補選択→金額入力→保存で
  `/voucher/entry/11` に遷移、ページエラー・フォームエラーなし。
  テスト証憑（id=11）は API で削除済み、DBに残骸なし。
