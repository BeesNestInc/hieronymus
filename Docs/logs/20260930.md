# 2026-09-30

## 年度ロック機能の実装

決算・繰越後の年度データを強い権限者でも編集不可にする年度ロックを実装。
`lockedAt` が NULL でなければロック中（`isLocked` カラムは持たない）。

### 変更内容

- DB: `migrations/20260930000000-add-lock-to-fiscal-years.cjs` 新規
  （`FiscalYears.lockedAt` DATE NULL、`lockedBy` INTEGER NULL）。
  test / development 両DBに `sequelize db:migrate` 適用済み。
- モデル: `models/fiscalyear.js` に2フィールド追加。
- 共通ヘルパ: `libs/fiscal-lock.js` 新規
  （`isLocked` / `findFiscalYearForDate` / `findFiscalYearForTerm` /
  `checkDateLocked` / `checkTermLocked` / `rejectIfLocked`）。
  ロック時の応答規約は HTTP 423 + `{code:-423, term}`。
- 書込ガード:
  - 振替伝票: `routes/api_cross_slip.js`（recalcReject=新規日付、update=新旧term、
    delete/approve=既存term）、`libs/cross_slip.js`（create/updateで
    `FiscalYearLocked` throw、route側で423に変換）
  - 明細直接更新: `routes/api_cross_slip_detail.js`（親slipのterm経由）
  - 証憑: `routes/api_voucher.js`（判定は `issueDate` のみ。
    POST/PUT=新日付、PUT/DELETE=旧日付も、upload/bind/deleteFile=親証憑の日付）
  - 取引文書: `routes/api_transaction_document.js`
    （POST/DELETE/book=既存日付、PUT=新旧両日付）
  - 期首残高: `routes/api_account.js`・`routes/api_sub_account.js`（対象term）
  - 年度設定: `routes/api-term.js:update`（`taxIncluded` 変更をロック中禁止）
- ロック操作: `PUT /api/term/:id/lock`（accounting/administrable）、
  `PUT /api/term/:id/unlock`（administrableのみ）。
  `libs/permission.js` にRULE追加（unlockを汎用term PUTより前に配置）。
- 繰越: `forms/closing.js` を `closing(term, user)` に拡張し、成功後に旧年度を
  自動ロック。ロック済み年度の再繰越は `FiscalYearLocked`→423。
  `routes/api.js`・`routes/home.js` からユーザ受け渡し。
- フロント: `front/svelte/home/term.svelte`・`widgets/term.svelte`
  （ロック列表示、ロック中は税込チェック無効、ロック/解除ボタン、423時アラート）。
- 対象外: 取引先等の年度に属さないマスタ（CRM兼用のため）。
  監査履歴は後日検討（解除時は lockedAt/lockedBy を NULL に戻すのみ）。
- 文書: `documents/fiscal-year.md` に「年度ロック」節追記。

## 追記: 不承認のサイレント失敗を修正

ロック年度の伝票で「不承認」を押すとエラーも出ず変更可能なフリになる問題。
原因は `cross-slip-modal.svelte` の `disapprove` がサーバ応答前に
ローカル `slip.approvedAt` を null に書き換え、失敗時の処理が無かったため。
（サーバ側は正しく423を返しており、実際には不承認になっていない）

修正: `approve`/`disapprove` は失敗時にローカル状態を復元してアラート表示。
423時はロック解除の案内文言。`save`/`delete_` にも `.catch` で同様の
アラートを追加。`npm run build` 再実行済み。

## 追記: ロック年度では操作ボタンを非表示に

ロックバナー表示（サーバ側423ガードは維持）。

ロック表示。`npm run build` 再実行済み。要アプリ再起動。
