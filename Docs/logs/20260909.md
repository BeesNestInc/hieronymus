# 2026-09-09 (Wed)

## 証憑詳細で相手先名が表示されない不具合を修正

`/voucher/entry/:id` で相手先名欄が空になる事象を調査・修正。
DB確認済みでデータ欠損ではないため、表示バグとして対応した。

### 原因

- `front/svelte/voucher/voucher-info.svelte` は `CompanySelect` に
  `companyId` しか渡さず、名前解決を子に丸投げしていた
  （他画面 `transaction-info` / `task-info` は `bind:companyName` 等を明示渡し）。
- `front/svelte/components/company-select.svelte` の名前解決は
  `onMount` の一回きり（`GET /api/company/` → `companyDecide(companyId)`）で、
  `companyId` がマウント後に確定・差し替えされる経路
  （`voucher.svelte` の二重 `checkPage`、保存後の `voucher` 差し替え）に追従しなかった。
- `voucher-info.svelte` の `companyKey = voucher.company.name` は子に渡らない
  デッドコードで、かつ `voucher.company == null` 時に例外で `onMount` を中断する恐れがあった。
- `register=true`（boolean）を渡していたが、子側の判定は `register === 'true'`
  （文字列）のため、登録ボタン表示条件が不成立だった。

### 対応

- `voucher-info.svelte`
  - `CompanySelect` に `voucher.company` の名前・担当者・郵便番号・住所を
    片方向プロップで渡すように変更（保存に使う `companyId` のみ `bind` 維持）。
  - `register="true"` に統一。
  - `voucher.company?.name ?? ''` にガード。
- `company-select.svelte`
  - `resolvedCompanyId` を導入し、`companyDecide` / `update` 成功時に記録。
  - 会社一覧取得後に `companyId` が未解決なら自動で `companyDecide` 再実行する
    リアクティブ文を追加。ユーザ検索中（候補リスト表示中）は上書きしない。

### 検証

- `npm run build` 成功（26.20s）。
- 実画面での表示確認はユーザ側で実施（対象IDで相手先名表示・保存後維持を確認予定）。
