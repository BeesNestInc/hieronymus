### 棚卸し（自動抽出スクリプトによる実測）

- 230エンドポイント登録（routes/api.js）を許可表（libs/permission.jsの
  RULES/PUBLIC_PATHS）と突合
- **未登録（全員403）**: 2件 — `GET /expense_report/merge_candidates` と
  `POST /expense_report/:id/merge_spend`。フロントから呼ばれている＝
  出金仮の手動統合UIが本番で403になる壊れた機能（**403石碑3度目**）
- **ANY更新系**: 32件（大半はhandler側で絞り込み済み。伝票削除=承認/作成者、
  精算書=作成者/会計、取込系=会計、付箋・マイページ=設計上全員、
  パスワード=自分のみ、など）
- **実質の穴**: ①伝票の新規作成が誰でも可 ②証憑一覧が無絞り込み
  ③他人の証憑へのファイル添付・bind・ファイル削除 ④他人の証憑へのOCR起動

### 設計判断（ユーザー決定）

- 伝票の新規作成 → **会計・承認権限に限定**
- 証憑一覧 → **作成者 or 会計に絞る**（一般ユーザーは自分の証憑だけ。
  経費精算の証憑候補は作成者本人が引くので影響なし）
- OCR起動 → **自分の証憑 or 会計に絞る**（multipart直接アップロードは
  従来どおり誰でも）
- 未登録2件 → handler側で会計/承認に絞り込み済みのため**表はANY登録**
  （expense_report系の既存パターン踏襲）

### 実装

- `libs/permission.js`:
  - POST /cross_slip を accounting/approvable に限定
  - merge 2APIを登録（403石碑の出自をコメントに記録）
  - `lintRoutes`/`concretePath`/`isRegistered` をexport（起動時lint用）
- `routes/api_voucher.js`:
  - upload(:id)/bind/deleteFile に作成者or会計のチェックを追加
  - 一覧getに createdBy による絞り込み（一般ユーザーは自分の証憑だけ）
  - 単体取得(:id)も同様に絞り込み（存在しない証憑は404を返すようになった）
- `routes/api_expense_report.js`:
  - ocr の voucherId 指定時に作成者or会計のみ許可
- `app.js`: 起動時に `/api` ルータをlintし、許可表未登録のエンドポイントを
  警告（403石碑は追加された瞬間にログに出る）
- `test/permission.test.js`: 新規39テスト
  - guard直叩きマトリクス（一般/会計/承認/管理/AI管理 × 28パターン）
  - 未登録ゼロlint（今後の追加忘れはテストで落ちる）
  - handler絞り込みの実DBテスト（他人の証憑の取得・更新・削除・添付・bind・
    ファイル削除・OCR → 全部拒否、bindの会計での通過、一覧の本人分だけ表示）
